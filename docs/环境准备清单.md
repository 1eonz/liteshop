# LiteShop 项目环境准备清单

> 本文件列出开发 LiteShop 所需的**电脑环境、软件、账户**。在另一台开发电脑上按此清单准备即可。
> 项目骨架代码由主 Agent 在 IDE 里现场生成，不需要预先创建。

---

## 一、硬件要求

| 项 | 最低 | 推荐 |
|---|---|---|
| CPU | 4 核 | 8 核 |
| 内存 | 8 GB | 16 GB |
| 磁盘 | 50 GB 可用 | 100 GB SSD |
| 网络 | 能访问 npm / pypi / Docker Hub / GitHub | — |

- 或 Linux（Ubuntu 22.04+）

## 三、必装软件清单

### 3.1 Node.js 22 LTS

**为什么**：前端构建工具链 + Codex CLI（若用 CLI 模式）+ 各种 npm 工具

**安装**：

```powershell
# 方式 1：官方安装包
# 下载 https://nodejs.org/dist/v22.11.0/node-v22.11.0-x64.msi 安装

# 方式 2：nvm-windows（推荐，便于多版本切换）
# 下载 https://github.com/coreybutler/nvm-windows/releases
nvm install 22.11.0
nvm use 22.11.0

# 验证
node -v   # v22.11.0
npm -v    # 10.x
```

### 3.2 pnpm 9

**为什么**：Monorepo 包管理，比 npm/yarn 快且省磁盘

```powershell
npm install -g pnpm@9
pnpm -v   # 9.x

# 推荐切淘宝镜像（国内加速）
pnpm config set registry https://registry.npmmirror.com
```

### 3.3 Python 3.12

**为什么**：后端 FastAPI

```powershell
# 方式 1：官方安装包
# 下载 https://www.python.org/downloads/release/python-3120/ 安装时勾选 "Add to PATH"

# 方式 2：pyenv-windows（推荐）
# https://github.com/pyenv-win/pyenv-win
pyenv install 3.12.0
pyenv global 3.12.0

python --version   # Python 3.12.0

# 推荐切清华镜像
pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple
```

### 3.4 uv（Python 包管理器，可选但推荐）

**为什么**：比 pip 快 10-100 倍，虚拟环境管理更简洁

```powershell
pip install uv
uv --version
```

### 3.5 Docker Desktop

**为什么**：本地起 PostgreSQL + Redis + Nginx

```powershell
# 下载 https://www.docker.com/products/docker-desktop/
# 安装后启动 Docker Desktop

docker --version
docker compose version
```

**Docker Desktop 配置**：
- 内存分配：至少 4GB
- 磁盘：至少 30GB
- WSL2 后端（Windows）

### 3.6 Git

```powershell
# 下载 https://git-scm.com/download/win
git --version   # 2.40+
git config --global user.name "你的名字"
git config --global user.email "your@email.com"
git config --global core.autocrlf input   # 跨平台换行符
```

### 3.7 CodeX IDE / VS Code

```powershell
# CodeX IDE（你使用的工具）
# 或 VS Code：https://code.visualstudio.com/
```

**必装扩展**：
- ESLint
- Prettier
- Python
- Pylance
- Tailwind CSS IntelliSense
- PostgreSQL
- Docker
- GitLens
- Console Ninja

### 3.8 PostgreSQL 客户端（可选）

- DBeaver：https://dbeaver.io/
- pgAdmin：https://www.pgadmin.org/
- Navicat（付费）

### 3.9 Redis 客户端（可选）

- RedisInsight：https://redis.io/insight/
- Another Redis Desktop Manager

## 五、环境变量模板

项目骨架生成后会有 `.env.example`（**单一可信源**），复制为 `.env.development` / `.env.staging` / `.env.production` 填入对应环境的密钥。

> 不在本文件重复字段清单，避免两处维护失同步。请直接打开根目录 `.env.example` 查看完整字段（含注释）。
> 主要分组：数据库（含连接池）/ Redis（含连接池）/ CORS+Cookie / 字段加密密钥 / JWT / 支付（含回调 URL）/ OSS（含内网 Endpoint）/ 文件上传限制 / 短信 / 邮件 / 官网 ISR / Sentry / 应用（含日志路径）/ 管理员初始化 / CAPTCHA / 主题模式 / 前端 / 限流 / WebSocket+SSE。

**必填项快速核对**（缺一不可启动）：
- `DATABASE_URL` / `REDIS_URL`：基础设施连接
- `JWT_SECRET`：认证必备，至少 32 字符随机串
- `FIELD_ENCRYPTION_KEY`：敏感字段加密（手机号/身份证），生成方式见 `.env.example` 注释
- `CORS_ORIGINS`：前后端分离必备，生产必须收紧为真实域名
- `PAYMENT_NOTIFY_BASE_URL` + `WECHAT_*_NOTIFY_URL` + `ALIPAY_*_NOTIFY_URL`：支付回调外网可达

**生产环境额外必填**：
- `COOKIE_SECURE=true` + `COOKIE_SAMESITE=none`（跨域 cookie）
- `OSS_INTERNAL_ENDPOINT`：ECS 走内网省流量
- `SENTRY_ENVIRONMENT=production`
- `CAPTCHA_APP_KEY` + `CAPTCHA_APP_SECRET`：登录防刷
- `ADMIN_INIT_USERNAME/PASSWORD`：首次部署后立即改密并清空

## 八、常见问题

### 8.1 pnpm install 慢

```powershell
pnpm config set registry https://registry.npmmirror.com
```

### 8.2 pip install 慢

```powershell
pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple
```

### 8.3 Docker Desktop 启动失败

- Windows：确保 WSL2 已安装 (`wsl --install`)
- macOS：确保 Intel/Apple Silicon 选对版本

### 8.4 PostgreSQL 连不上

```powershell
# 检查容器
docker ps
# 检查端口
netstat -ano | findstr 5432
# 重启
docker compose restart postgres
```

### 8.5 Redis 连不上

```powershell
docker compose restart redis
redis-cli ping   # 应返回 PONG
```

### 8.6 端口被占用

```powershell
# 查占用
netstat -ano | findstr :8000
# 杀进程
taskkill /PID <PID> /F
```

## 九、项目启动流程（环境准备好之后）

环境准备好后，在 IDE 里打开 `liteshop/` 目录，把 `提示词.md` 里"启动主 Agent 的提示词"整段复制粘贴到对话窗发送即可。主 Agent 会：

1. 读 `docs/PRD-v1.3.md` 和 `AGENTS.md`
2. 现场生成项目骨架（package.json、pnpm-workspace.yaml、turbo.json、docker-compose.yml、各 packages 目录、backend 目录等）
3. 现场拆计划写 `plans/plan-{i}.md`
4. 用 AskUserQuestion 展示计划清单请用户确认
5. 串行调度子 Agent 执行每个计划
6. 每个子 Agent 完成后做 5 步验收
7. 全部完成后汇报进度，请你合并 main
