# LiteShop 可观测性规范

> 本文件定义 LiteShop 项目的监控指标、告警阈值、SLO/SLI、链路追踪、日志规范。
> 主 Agent 在 plan-04 backend 骨架阶段生成 `backend/app/core/observability.py`：1a 期交付 Sentry 初始化 + `/health` 端点 + structlog 结构化日志；Prometheus 指标埋点代码随骨架生成（服务端部署为 1b 期）；OpenTelemetry 全链路为增长期。

---

> **分期适用（唯一事实源：AGENTS.md §十四 运维能力分期适用矩阵）**
>
> | 能力 | 1a 期（必须） | 1b 期 | 增长期（触发：日订单 > 2000） |
> |---|---|---|---|
> | 监控 | Sentry + /health + 结构化日志 | + Prometheus 基础指标 | + Grafana / SLO / 告警 |
>
> 本文中的 SLO 错误预算、Prometheus/Grafana 告警体系、OpenTelemetry 全链路 Trace 均为**增长期参考**，不作为 1a 期验收项；1a 期只须交付 Sentry 错误上报 + `/health` 端点 + 结构化日志。

## 二、SLI / SLO 目标

### 2.1 核心服务 SLO（1a 期目标）

| 服务 | SLI 指标 | SLO 目标 | 测量窗口 | 违反后果 |
|---|---|---|---|---|
| API 网关 | 可用性（5xx 错误率） | 99.9% | 30 天 | 告警 + 复盘 |
| API 网关 | 延迟（P99 RT） | < 500ms | 5 分钟 | 告警 |
| 下单接口 | 成功率（非 5xx） | 99.5% | 5 分钟 | P0 告警 |
| 支付回调 | 成功率 | 99.95% | 5 分钟 | P0 告警 |
| 库存扣减 | 超卖次数 | 0 | 实时 | P0 告警 |
| 前端 H5 | 首屏 LCP | < 2.5s | 7 天 | 告警 |
| 前端 H5 | JS 错误率 | < 0.5% | 30 天 | 告警 |
| PostgreSQL | 可用性 | 99.95% | 30 天 | P0 告警 |
| Redis | 可用性 | 99.95% | 30 天 | P0 告警 |

### 2.2 错误预算

按 SLO 99.9% 可用性计算，30 天错误预算 = 30 × 24 × 60 × 0.001 = **43.2 分钟**。

- 错误预算未耗尽：可发版、做实验
- 错误预算已耗尽 50%：暂停发版，优先稳定性改进
- 错误预算已耗尽 100%：冻结所有非 Hotfix 发版

## 三、指标定义（Prometheus Metrics）

### 3.1 系统指标（node_exporter 自动采集）

| 指标 | 说明 | 告警阈值 |
|---|---|---|
| `node_cpu_seconds_total` | CPU 使用率 | > 80% 持续 5 分钟 |
| `node_memory_MemAvailable_bytes` | 可用内存 | < 10% 总内存 |
| `node_filesystem_avail_bytes` | 磁盘可用空间 | < 15% 总容量 |
| `node_disk_read_time_seconds_total` | 磁盘 IO | await > 50ms 持续 5 分钟 |

### 3.2 应用指标（自定义埋点）

```python
# backend/app/core/observability.py

from prometheus_client import Counter, Histogram, Gauge

# ===== HTTP 请求指标 =====
http_requests_total = Counter(
    'liteshop_http_requests_total',
    'Total HTTP requests',
    ['method', 'endpoint', 'status']
)

http_request_duration_seconds = Histogram(
    'liteshop_http_request_duration_seconds',
    'HTTP request duration',
    ['method', 'endpoint'],
    buckets=[0.05, 0.1, 0.25, 0.5, 1.0, 2.5, 5.0, 10.0]
)

# ===== 业务指标 =====
orders_created_total = Counter(
    'liteshop_orders_created_total',
    'Total orders created',
    ['status']  # pending/paid/shipped/completed/cancelled
)

payments_processed_total = Counter(
    'liteshop_payments_processed_total',
    'Total payments processed',
    ['provider', 'result']  # wechat/alipay, success/fail
)

payment_callback_received_total = Counter(
    'liteshop_payment_callback_received_total',
    'Payment callbacks received',
    ['provider', 'result']  # success/duplicate/failed
)

# 库存指标
stock_locked_total = Gauge(
    'liteshop_stock_locked_total',
    'Total locked stock across all SKUs'
)

stock_oversold_events = Counter(
    'liteshop_stock_oversold_events_total',
    'Stock oversold events (should be 0)'
)

# ===== 基础设施指标 =====
db_connections_in_use = Gauge(
    'liteshop_db_connections_in_use',
    'Database connections in use'
)

redis_operations_total = Counter(
    'liteshop_redis_operations_total',
    'Redis operations',
    ['operation', 'result']  # get/set/delete, hit/miss/fail
)

# ===== 幂等指标 =====
idempotency_cache_hits = Counter(
    'liteshop_idempotency_cache_hits_total',
    'Idempotency cache hits (duplicate requests blocked)'
)
```

## 四、告警规则（Alertmanager）

### 4.1 告警分级

| 级别 | 响应 SLA | 通知方式 | 触发条件示例 |
|---|---|---|---|
| **P0 紧急** | 15 分钟 | 电话 + 短信 + 钉钉 | 全站宕机 / 支付失败率 > 5% / 库存超卖 |
| **P1 严重** | 1 小时 | 钉钉 + 短信 | API 5xx 错误率 > 1% / P99 > 2s / DB 连接池满 |
| **P2 警告** | 4 小时 | 钉钉 | CPU > 80% / 磁盘 < 15% / 慢查询增多 |
| **P3 提醒** | 不响应 | 邮件 | 告警恢复 / 日常报表 |

### 4.2 告警规则定义

```yaml
# alerts.yml
groups:
  - name: liteshop-critical
    rules:
      # P0 - 库存超卖（零容忍）
      - alert: StockOversold
        expr: liteshop_stock_oversold_events_total > 0
        for: 0m
        labels:
          severity: P0
        annotations:
          summary: "库存超卖事件"
          description: "检测到库存超卖，立即排查"

      # P0 - 支付回调失败率高
      - alert: PaymentCallbackFailureRate
        expr: |
          rate(liteshop_payment_callback_received_total{result="failed"}[5m])
          / rate(liteshop_payment_callback_received_total[5m]) > 0.05
        for: 2m
        labels:
          severity: P0
        annotations:
          summary: "支付回调失败率 > 5%"

      # P0 - 全站 5xx 错误率
      - alert: HighErrorRate
        expr: |
          rate(liteshop_http_requests_total{status=~"5.."}[5m])
          / rate(liteshop_http_requests_total[5m]) > 0.01
        for: 5m
        labels:
          severity: P0

      # P1 - API 延迟过高
      - alert: HighLatency
        expr: |
          histogram_quantile(0.99,
            rate(liteshop_http_request_duration_seconds_bucket[5m])) > 2
        for: 5m
        labels:
          severity: P1

      # P1 - DB 连接池使用率
      - alert: DBConnectionPoolFull
        expr: |
          liteshop_db_connections_in_use / 30 > 0.8
        for: 5m
        labels:
          severity: P1

      # P2 - 库存预警
      - alert: LowStockWarning
        expr: liteshop_low_stock_skus > 10
        for: 30m
        labels:
          severity: P2
```

### 4.4 告警抑制与聚合

```yaml
route:
  group_by: ['alertname', 'cluster']
  group_wait: 30s      # 首次告警等待 30s 聚合
  group_interval: 5m   # 后续每 5m 发一次
```

## 五、日志规范

### 5.1 日志级别使用规约

| 级别 | 使用场景 | 示例 |
|---|---|---|
| `DEBUG` | 开发调试，生产关闭 | 变量值/中间状态 |
| `INFO` | 业务关键节点 | 订单创建/支付成功/用户注册 |
| `WARNING` | 异常但可恢复 | 幂等拦截/库存预警/限流触发 |
| `ERROR` | 业务异常 | 支付失败/DB 超时/外部 API 5xx |
| `CRITICAL` | 系统级故障 | DB 连接断开/Redis 宕机/启动失败 |

### 5.2 结构化日志格式（PRD E13）

```python
# 所有日志必须结构化，含以下字段
{
    "timestamp": "2026-09-05T10:30:45.123Z",
    "level": "INFO",
    "event": "order.created",
    "request_id": "req_abc123",      # 贯穿整个请求链
    "user_id": 1001,
    "order_id": 50001,
    "amount": 19990,                 # 整数分
    "duration_ms": 45,
    "module": "app.services.order",
    "extra": {}
}
```

### 5.3 敏感字段脱敏

```python
# 日志输出前必须脱敏的字段
SENSITIVE_FIELDS = [
    'phone', 'mobile', 'id_card', 'password',
    'token', 'secret', 'api_key', 'private_key',
    'bank_card', 'cvv', 'openid'
]

# 脱敏规则
# phone: 138****8888
# id_card: 330***********1234
# bank_card: 6222 **** **** 1234
# password: ***REDACTED***
```

### 5.4 慢日志监控

| 类型 | 阈值 | 处理 |
|---|---|---|
| 慢 SQL | > 500ms | 记录到 `slow_queries` 日志，每天汇总 |
| 慢 HTTP 请求 | > 2s | 记录到 `slow_http` 日志，Prometheus 计数 |
| 慢 Redis 操作 | > 50ms | 记录到 `slow_redis` 日志 |

### 5.5 日志归档

| 环境 | 保留期 | 归档方式 |
|---|---|---|
| development | 7 天 | 本地文件 + 滚动 |
| staging | 30 天 | Loki + S3 归档 |
| production | 90 天 | Loki + S3 归档，3 个月后转冷存储 |

## 六、链路追踪（OpenTelemetry）

### 6.1 接入方式

```python
# backend/app/core/tracing.py
from opentelemetry import trace
from opentelemetry.sdk.trace import TracerProvider
from opentelemetry.sdk.trace.export import BatchSpanProcessor
from opentelemetry.exporter.jaeger.thrift import JaegerExporter

def setup_tracing(app_name: str, jaeger_endpoint: str):
    provider = TracerProvider()
    provider.add_span_processor(
        BatchSpanProcessor(
            JaegerExporter(
                agent_host_name=jaeger_endpoint,
                agent_port=6831,
            )
        )
    )
    trace.set_tracer_provider(provider)
```

### 6.2 Span 命名规约

```
{service}.{module}.{operation}
```

示例：
- `liteshop.order.create` - 创建订单
- `liteshop.payment.callback` - 支付回调
- `liteshop.stock.lock` - 锁定库存
- `liteshop.db.query.orders` - DB 查询
- `liteshop.redis.get.lock` - Redis 操作

### 6.3 Span 标签

每个 Span 必含以下标签：

| 标签 | 说明 |
|---|---|
| `request_id` | 请求唯一 ID，贯穿全链路 |
| `user_id` | 用户 ID（如有） |
| `otel.status_code` | OK / ERROR |
| `otel.status_description` | 错误描述（如有） |
| `biz.operation` | 业务操作名（如 `order.create`） |

## 七、Sentry 错误监控（PRD E14）

### 7.1 初始化

```python
import sentry_sdk
from sentry_sdk.integrations.fastapi import FastApiIntegration
from sentry_sdk.integrations.sqlalchemy import SqlalchemyIntegration

sentry_sdk.init(
    dsn=settings.SENTRY_DSN,
    environment=settings.ENV,
    traces_sample_rate=0.1,          # 10% 采样
    integrations=[
        FastApiIntegration(),
        SqlalchemyIntegration(),
    ],
    before_send=filter_sensitive_data,  # 敏感字段过滤
)
```

### 7.2 敏感字段过滤

```python
def filter_sensitive_data(event, hint):
    for exc in event.get('exception', {}).get('values', []):
        for frame in exc.get('stacktrace', {}).get('frames', []):
            for var_name in list(frame.get('vars', {}).keys()):
                if var_name.lower() in SENSITIVE_FIELDS:
                    frame['vars'][var_name] = '***REDACTED***'
    return event
```

### 7.3 Release Tag

每次发版必须打 release tag：

```python
sentry_sdk.init(
    release=f"liteshop-backend@{settings.APP_VERSION}",
)
```

## 八、前端监控

### 8.1 Web Vitals（H5 + Admin）

```typescript
// packages/h5-app/src/utils/web-vitals.ts
import { onLCP, onFID, onCLS, onINP } from 'web-vitals';

onLCP(metric => reportMetric('LCP', metric));
onFID(metric => reportMetric('FID', metric));
onCLS(metric => reportMetric('CLS', metric));
onINP(metric => reportMetric('INP', metric));

function reportMetric(name: string, metric: any) {
  // 发送到 Sentry
  Sentry.captureMessage(`web-vital-${name}`, {
    level: metric.value > THRESHOLDS[name] ? 'warning' : 'info',
    extra: { value: metric.value, id: metric.id },
  });
}
```
