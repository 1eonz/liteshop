## 完整流程速查

```
第一步：输入一条指令 → Agent 自动装 Skills + 初始化项目 + 生成骨架
  ↓
第二步：输入一条指令 → Agent 读所有文档 + 设计 3 个 Demo → 你浏览器选风格 → 确认
  ↓
第三步：输入一条指令 → Agent 全自动编码 + 测试 + 修复 + 验收 + 部署
  ↓
完成：LiteShop 上线，可商用
```

**你全程只需：复制粘贴 3 条指令 + 浏览器选 Demo + 几次 yes/no 确认。**

## 第一步：Agent 自动安装 Skills + 初始化项目

### 1.1 准备环境（一次性，你手动做）

按 `docs/环境准备清单.md` 准备好电脑环境（Node 22 / pnpm 9 / Python 3.12 / Docker / Git / CodeX IDE）。

打开 CodeX IDE → 打开 `liteshop/` 目录 → 在聊天窗口复制粘贴：

```
   1. frontend-design
   2. frontend-ui-ux
   3. better-interface
   4. impeccable               # AI 设计词汇层：反模式库 + 23 条设计命令 + CI 设计检测
   5. code-reviewer
   6. frontend-code-review
   7. react-best-practices
   8. webapp-testing
   9. fix
   10. git-commit
   11. pr-creator
   12. update-docs

B. 创建项目配置：
   12. 创建 .codex/skills/ 目录
   13. 创建 5 个项目自定义 Skills：
       - .codex/skills/project-radar/SKILL.md（项目雷达：通用全局 Skill 副本，5 层识别项目类型+动态生成配置包+分析风险+提示用户调整+需求覆盖检查+生成 project-context.md，已存在）
```

## 第三步：主 Agent 全自动编码 + 测试 + 验收 + 部署

### 3.1 你只需输入一条指令

在 CodeX 聊天窗口复制粘贴：

```
风格已确认。现在开始全自动开发 LiteShop 1a 期，你自主完成以下全部流程，不需要我干预：

=== 步骤 5.0：项目雷达扫描（project-radar skill，通用全局 Skill）===
启动后第一时间调用 project-radar skill（5 步：扫描→分析→提示→覆盖检查→生成）：
1. 5 层项目识别（L0 配置文件→L1 目录结构→L2 依赖关键词→L3 PRD 关键词→L4 代码模式），综合判断项目类型
2. 按识别结果动态生成项目专属配置包到 .codex/skills/project-radar/profiles/{type}.md（不预创建，现场生成）
3. 分析风险：基础 14 类 + 配置包专属风险（动态加载）+ 条件触发（契约/幂等按项目类型）+ 额外检测项（幻觉依赖/CSS 硬编码/构建体积/测试框架/CI 配置）

**PRD 分层读（禁一次读全 PRD 25 万字符）**：

契约确认后，更新 .codex/project-context.md（shared-types 章节已可填充）。

=== 现场拆计划 ===
第 1 层读 PRD 目录 + §7.1 MVP 清单 + §D8.1 阶段表（~1 万 token）。
第 2 层读 plan 对应的 PRD 附录章节，把 PRD 需求翻译成 plan 的任务清单。
写 plans/INDEX.md + plans/plan-01.md ~ plans/plan-13.md。
每个 plan 文件必须含**完整任务清单**（主 Agent 已把 PRD 需求翻译好，子 Agent 只读 plan 不读 PRD）。
每个 plan 文件顶部标注"PRD 章节：D1.1+E3.1"（供主 Agent 第 2 层读时参考）。
按依赖驱动：
  plan-01~03: shared 层（types/tokens/components）
  plan-04~06: backend（骨架/商品库存/订单支付）
  plan-07~09: h5-app（骨架/商品浏览/购物车下单支付）
  plan-10~12: admin-app（骨架/商品订单/库存运费设置）
  plan-13: 集成验证

=== 需求覆盖检查 ===（project-radar skill）

- 自适应关键词探测：4 组关键词（checklist 类/版本标注类/模块编号类/验收类），选命中最多的 2 组
- 用自适应关键词提取 PRD 所有需求点
- 自适应任务载体对照：自动识别 plans/phases/tasks/issues，在该载体文件里搜索需求点
- 发现遗漏 → AskUserQuestion 提示"以下需求未拆到任务"
- 我确认后补拆任务或加到已有任务的任务清单
- 更新 project-context.md 的需求覆盖矩阵

  h. 每 3 个 plan 完成后：调用 project-radar 重新扫描更新的目录，增量更新 project-context.md 的代码索引；同时压缩主 Agent 上下文，丢弃已完成 plan 的 final summary 全文和验收输出，只保留"给下一个的提示"和 pass/fail 结论。用 AskUserQuestion 同步进度。

- 调用 frontend-code-review skill 审查前端

- 调用 better-interface skill 审查 a11y

- 调用 impeccable /harden 生产就绪检查

- 按 PRD E15.1/E15.2/E15.3 + 补充项检查全部验收点

=== 部署上线 ===
我确认验收通过后：

注意事项：
1. 严格遵循 AGENTS.md 的所有规则
2. 严格遵循 docs/设计规范.md（用确认的 Demo 风格）
3. 严格遵循 docs/PRD-v1.3.md 附录 D/E 的所有设计决策

8. 金额一律整数分
9. 架构变更/合并 main/push 远程/新依赖引入 → 用 AskUserQuestion 请示我
```

## 常见问题

### Q：Agent 卡住了怎么办？
A：在聊天窗口输入"继续"或"跳过当前步骤，进入下一步"。

### Q：Agent 生成的代码不符合规范怎么办？
A：输入"请检查 AGENTS.md 和 docs/设计规范.md，修正不符合规范的地方。调用 code-reviewer skill 审查"。

### Q：Demo 风格不满意怎么办？
A：输入"Demo X 的 XX 部分不好，请改成 YY 风格"。

### Q：想中途暂停怎么办？
A：直接关闭 CodeX 窗口，下次打开输入"继续上次的项目开发"。

### Q：Agent 上下文太满怎么办？
A：输入"压缩上下文，保留当前 plan 进度和关键决策"。

### Q：额度快用完了怎么办？
A：简单任务（写测试、改文案、格式化）切便宜模型，复杂任务（架构/支付/状态机）用最强模型。

### Q：某个 Skill 的规则和项目设计系统冲突怎么办？
A：Agent 会在 SKILL.md 末尾自动加"优先遵循项目 docs/设计规范.md，不覆盖自定义 CSS 变量"。

### Q：如何查看 Agent 当前进度？
A：输入"查看当前进度：读 plans/INDEX.md，跑 git log --oneline -20，汇报已完成几个 plan、当前在哪个 plan、有哪些阻塞项"。

## 关键原则

1. **你不写代码**：所有代码由子 Agent 写
2. **你不跑命令**：所有命令由主 Agent 跑，你只审批 RunCommand

4. **你做验收**：Demo 风格选择、最终验收报告确认
5. **你做部署**：确认部署、配置域名/证书
