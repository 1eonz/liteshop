# LiteShop 架构说明

> 重构计划：[plan-39](../plans/plan-39.md)。进度与验证：[当前交接](交接文档-当前阶段.md)。

## 系统形态

一个模块化 FastAPI 应用服务 H5 商城、Admin 后台、Next.js 官网。PostgreSQL 保存业务事实，Redis 承担短期状态、限流和并发协调。不为未来假设拆微服务或增加通用框架。

| 目录 | 职责 |
|---|---|
| `packages/h5-app` | 浏览、购物、账户与交易界面 |
| `packages/admin-app` | 运营、审核与页面配置 |
| `packages/site-app` | 官网内容、SEO 与展示 |
| `packages/shared-types` | API/Schema 领域类型、枚举和金额格式化 |
| `packages/shared-tokens` | 设计变量 |
| `packages/shared-components` | 已有跨端组件与防重复操作 Hook |
| `packages/ui-kit` | 尚未完成调用方迁移的 UI 原型，不强制重写现有页面 |
| `packages/shared-3d-components` | 目前只有配置和能力判断，还不是 3D 渲染器 |
| `backend/app` | HTTP、用例、持久化和基础设施 |

## 前端：状态只拥有一次

请求路径：`页面 → 领域 query/mutation → service HTTP 方法 → 后端`。

- React Query 拥有服务端缓存、加载/失败状态和失效，不再复制进 Zustand。
- Zustand 拥有登录会话和本地购物选择；表单、弹层、选中项留在页面局部。
- `features` 容纳跨页面能力或真实领域规则；一次性组件放在页面旁边。
- `service` 是 HTTP 边界。返回结构校验在边界做；未知 Schema、存储和 URL 仍是不可信输入。
- 删除零消费者兼容出口，不靠多层 `index.ts` 制造分层。公共包已发布接口仍遵循兼容要求。
- H5 首页只走 SchemaRenderer；搭建器文字画布不能宣称等于真实预览。
- 真实空数组就是空态；开发演示只能在明确开发分支出现，不覆盖权限/业务错误。
- 令牌刷新单飞、一次重试上限、写请求 ID 和写按钮防重复属于必要行为，不能为缩短文件删除。

## 后端：事务包住一个用例

调用方向：`api → services → repositories → models`。

- API 处理输入、认证、HTTP 映射；服务处理状态转换、权限、金额、库存、审计；仓储只访问数据。
- 用例决定事务边界，仓储不自行提交。库存和状态并发由数据库约束、原子 SQL、行锁保证。
- Redis 幂等锁防并发执行，数据库唯一记录保留提交结果，职责不同，不能简单删一层。
- 领域服务只初始化所需依赖。四重继承 Admin facade 是本轮待移除项，目标是明确领域入口加轻量权限/审计能力。
- 列表只查展示需要的数据，详情才加载完整聚合；先减少无用 SQL 和负载，再考虑缓存。
- 不并发共用 AsyncSession，不引入未经测量的缓存。
- 内存开发模式与数据库模式仍并存；测试必须标明覆盖哪一种。

## 交互、设计与 3D

使用已有 token 与组件，收敛重复 CSS。按钮有真实动作或明确禁用理由；保留加载、空态、错误恢复、键盘焦点。设计示例的身份、价格、指标不能替代业务数据。

3D 逐级增强：静态图可用 → 可见时加载 → 支持时渲染 → 离屏/隐藏暂停。移动端、低性能设备、减少动画和 WebGL 失败有静态路径；产品展示不抢滚动。Three/R3F/GLB 仍需依赖、资源与位置确认，CSS 动画和“360°”字样不算真实实现。

## 删除、合并与保留

1. 无消费者且不是契约要求的代码，删除。
2. 只有转发而没有语义边界的层，合并。
3. 同一事实多份状态、同一规则多份实现，统一所有权。
4. 保护真实输入、并发、权限边界的检查，保留并用行为测试证明。
5. 正确性、查询/请求数量、构建体积和交互状态可验证，才称为改进。

本轮内部重构不自动授权更换技术栈、契约、数据库结构或发布方式。验收结论必须附当次命令与环境限制，不复制旧数字。
