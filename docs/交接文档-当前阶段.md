## 本阶段发现并修复的问题

- 售后 OpenAPI 初版把 `schemas` 错放在 `components` 外层，且遗漏退货物流和后台审核接口；已按真实 FastAPI 路由重写并结构化解析验证。
- 新增 `expiredAt` 后，测试用的 `SimpleNamespace` 没有该属性导致订单地址测试失败；已用 `getattr` 兼容测试替身，并补齐内存响应字段。
- 售后单测初版假仓储缺少 `get_for_update`，导致退货状态测试无法进入业务判断；已补足最小仓储协议并通过全量测试。
- H5 首次 typecheck 使用了未重新构建的共享类型 dist，导致 `expiredAt` 类型暂时不可见；以后修改共享包后必须先 build 再跑消费者检查。
- 搭建器官网模式初次只改变文案，没有隔离组件面板和画布宽度；已改为 channel 驱动的组件分组和 375/1200 Token 宽度。
- RBAC/评价回复首轮实现后，mypy 暴露 SQLAlchemy `ScalarResult` 推断为 `Any`；通过仓储边界的精确 `cast` 修复，避免向服务层泄漏 Any。
- OpenAPI 评价契约首次插入商家回复字段时缩进错误，结构化解析立即捕获并修正；以后每次契约编辑必须先跑全目录 YAML 解析。
- 集成测试首次直接设置 `LITESHOP_RUN_INTEGRATION=1`，但遗漏 `LITESHOP_USE_DATABASE=true`，导致幂等操作拿到 `None` 会话；以后统一使用 `scripts/test.ps1 -Integration` 或同时设置两个变量。
- Docker Engine 曾在复跑前暂时不可用，启动 Compose 后服务恢复；基础设施门禁必须先检查 `docker compose ps` 再判断集成测试结果。
- `deploy.ps1` 原先实际只启动本地 Compose，名称与生产发布语义冲突；已拆出 `start-infra.ps1`，并让部署入口在缺少生产参数时失败关闭。
- 根级 Prettier 脚本依赖 `npx --yes prettier@3.6.2`，本地未安装 `prettier`，因此直接执行 `pnpm exec prettier` 会失败；后续格式化应使用项目既有 `pnpm format`/`pnpm format:check`。
- UI Kit 方案文档曾在包创建后仍标记为“不得创建”；本轮已同步方案、plan-37 和计划索引。后续需保持“代码状态变更后立即更新交接/计划文档”的习惯，避免下一轮 Agent 依据过期阻塞信息工作。

## 后续开发约定

- 前端按视图层、组件层、features 状态数据层、service API 层、store、hooks、utils、router 分层；页面 JSX 必须分行格式化。
- 后端保持 `api → services → repositories → models`，写操作事务化、Redis/DB 双层幂等，API 不直接操作 ORM。
- 注释使用中文，禁止 `any`；金额统一整数分；所有写操作按钮使用共享 `useDebounceAction`；React Query mutation 设置 `retry: 0`。
- 类型优先从 `@liteshop/shared-types` 导入；API 与 `docs/api-contracts/v1/` 同步；不重复定义组件、枚举和错误码。
- UI 继续沿用确认的珊瑚红画廊风格，颜色/字号/间距/圆角/阴影只用 Design Tokens。
- 主 Agent 完成每个阶段后主动 review、修复、验证并继续，不等待用户逐次追问；子 Agent 不作为进度阻塞。
- sync/await 用于事务、轮询、补偿和多分支；简单一次性解包可用 `.then`，同一函数不混用且完整传播 rejection。
