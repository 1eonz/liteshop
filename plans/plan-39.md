## 判断标准

“更优”以可验证结果衡量：更少重复数据源/调用跳转、更少查询与资源下载、可理解的依赖、正确的操作反馈。不承诺未经测量的“性能最高”。

保留的防护：外部输入验证、鉴权/RBAC、金额和库存约束、事务/行锁、支付验签、幂等、防重复提交、资源清理、减少动画。它们保护真实业务不变量。

优先删除的复杂度：无调用方兼容层、纯转发的多级出口、重复条件/序列化、同时维护的同义状态、没有消费者的扩展框架、假成功/假数据掩盖错误、叠加覆盖的废弃 CSS。

| 层 | 证据/风险 | 处理 |

| 前端状态 | HTTP 客户端两端重复；查询 hooks 到 service 多级聚合；演示回退散布 | 删除零消费者出口；仅在真实外部边界校验；不因减代码移除 refresh 单飞及 401 重试上限 |
| 渲染与样式 | styles.css 追加多批覆盖；Schema 与编辑器仅文字预览；静态 3D 被标成 360° | 按已有组件收口样式；如实记录预览能力差距；先修 3D 回退 |
| API 与服务 | AdminService 四重继承；权限调用也初始化商品/订单/库存/运费依赖 | 改为明确领域服务入口与轻量公共权限/审计能力，保持契约和事务 |
| 数据访问 | list_spus 预加载完整规格和值而摘要不使用 | 列表只加载必要 SKU；详情保留完整预加载；测试证明响应不变 |
| 交易与安全 | Redis+DB 幂等、行锁、refresh 单飞属于实际并发保护 | 审查正确性，不以“过度防御”为由删除；变更需要相应行为测试 |
| 文档 | 主 PRD 仅到 §7，附录散落 4 个无语义分片；多份交接重复且测试数冲突 | 单一阅读入口、明确现状/目标/历史；合并分片及历史，不丢独有需求 |

补充审查：Site `loadSitePage` 对 404 同样回退到静态页面、`loadSitePageSlugs` 将成功空列表替换为本地 slug，会让未发布页面继续出现；应区分“服务故障”与“后端明确不存在/空列表”。Admin 看板把累计销售额标成“今日销售额”，商品总量标成“在售商品”，应修正展示标签，不能擅改统计口径。

搭建器审查：`useAutoSave` 依赖每次 render 新建的回调，定时器不断重建；`usePageHistory` 在 state updater 内调用其他 setter，撤销状态分散。重构为一个历史状态转换，保留 50 步上限；自动保存使用稳定回调与真实写入结果。对历史顺序、分支编辑清空 redo、上限做行为测试。

文档与业务冲突（不在本次样式/内部重构中擅改）：PRD/AGENTS 的售后状态为 `GOODS_RETURNED/REFUNDED/REFUND_FAILED/CLOSED`，现行 OpenAPI 与前后端实际为 `WAITING_RETURN/RETURNED/COMPLETED/CANCELLED`。当前契约三端一致，但需求文档不一致；本轮保持已运行状态机，后续确认产品口径后统一文档或单独做兼容迁移，不能直接改枚举。
